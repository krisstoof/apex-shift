## Author and export

Use a licensed SpeedTree Modeler with a verified `.st9` exporter. Preserve editable authoring sources alongside the export or record their repository path in `source`. Build organic, stylized realistic/hand-painted tropical silhouettes readable from the isometric camera: asymmetric branches, trunk taper/lean, layered crowns and believable fern/frond shapes. Palms require fronds, not broadleaf spheres; broadleaf canopy must not resemble broccoli. Vines in this set are ground/creeping/cascading decorations, never attached-tree gameplay. Do not replace missing species with conifers, old FBX or Blender primitives.

Work in meters. Put the ground/trunk base at origin; compensate authoring units in the importer, not in wrapper scale. Target the manifest height ranges. Trees/dead trees require at least LOD0/1/2, with final billboards when supported. Target canopy triangles 15k/8k/4k per three geometric LODs; shrub/fern 5k/2.5k with two LODs where worthwhile. These are soft budgets, not measured results for this scaffold. Retain Games wind data in actual native exports. Review subtle trunk sway, frond/leaf motion and transitions in Unity; do not substitute VFX wind or a generic URP/Lit material.

Only after actual authoring fill `source`, `vendor`, `license`, `attribution`, `authoringReviewed`, `windReviewed`. For wholly project-authored assets a valid source description may be **Project-authored with SpeedTree Modeler**, plus the editable repository source path and actual author/tool/license record. Do not enter that label for uncreated or purchased content. External models/textures require real vendor/source, recorded redistribution license and any required attribution before commit; no third-party downloads were performed by this task.

Measure each harvestable model's trunk radius, collision height and center Y in meters; fill `trunkRadius`, `trunkHeight`, `trunkCenterY`. Zero prevents activation; guessed shared default dimensions are not measurements. Retain existing depleted/stump prefab references; null is allowed and must not be replaced with an invented stump. A curved palm may have a rotated child capsule carrying `VegetationTrunkCollider`; its real dimensions must match the recorded measurements. The existing promoter reuses marked colliders; otherwise it adds the measured trunk at runtime.

## Import, build and bind

Unity's native importer creates a prefab with LODGroup for SpeedTree exports; `.st9` has its own Wind tab. See [Unity SpeedTree import settings](https://docs.unity.com/en-us/engine/6000.0/manual/creating-environments/script-terrain/terrain-trees/speed-tree/class-speed-tree-importer). Import genuine `.st9` files with accessible texture dependencies, correct meter scale and the native `Universal Render Pipeline/Nature/SpeedTree9_URP` shader. The shader name and `_MainTex` atlas property are verified against the installed URP 17.6 package source. Confirm ST9 uses `UnityEditor.SpeedTree.Importer.SpeedTree9Importer`; the legacy `SpeedTreeImporter` handles older formats. Keep smooth LOD/crossfade and native wind-capable materials, mesh channels, alpha clipping and billboard configuration. Review shader errors, magenta/missing textures and wind in a graphical Unity session.

1. Run **Apex Shift/World/Build Tropical SpeedTree Wrappers** after all 26 real models import successfully. The builder preflights every model before writing wrappers. It does not author or export vegetation.
2. Each wrapper has an identity root and an identity nested native `SpeedTreeModel` child. Imported LODGroup/materials remain in that child; gameplay belongs to the wrapper root. No tree ResourceNodeView, TreeId or HarvestableTreeRuntime is baked into normal tree wrappers.
3. Run **Apex Shift/Validation/Validate Tropical SpeedTree Readiness**. It lists every absent export/wrapper and rejects missing scripts/meshes/materials/texture references, missing color atlas, non-native shader/importer/dependency, wrong nested model, scale/pivot/height problems, insufficient tree LODs, unintended colliders, unmeasured trunks and incomplete provenance/review records.
4. Run **Apex Shift/World/Bind Tropical SpeedTree Vegetation** only with a complete ready set. Preflight happens **before** creator updates so a missing model cannot even rewrite legacy/manual data. Complete readiness includes the non-procedural hero. There is no partial activation or fallback visual.
5. Binding updates the 25 species and exact five profiles in one rollback transaction, reusing the existing four IDs/GUIDs, preserving depleted references and retaining `tree_conifer_01` for compatibility. Hero never enters the catalog or procedural profiles. Only owned vegetation assets and the existing data anchor are saved; RuntimeWorld is not rewritten.
6. After activation **Create or Update Vegetation Data** keeps the 26-entry catalog (25 active + compatibility conifer), reuses existing manually assigned visuals/depleted references, and loads a canonical wrapper only for a null visual. A missing canonical wrapper is an explicit error, never an arbitrary ES fallback.

Re-export to the same `.st9` path and keep its `.meta`. Unity propagates the native reimport through nested prefab instances. Rebuilding an existing wrapper retains its GUID and manual root gameplay/collider configuration, does not replace the nested source with an arbitrary model, and validates existing transforms/contracts. Fix invalid manual settings explicitly rather than losing them on rebuild. Keep wrapper `.meta` files. A new variant requires a manifest entry, compatible habitat eligibility and weights, real native export, provenance/measurements/QA, updated counts/tests, then a complete preflight and bind.

## Gameplay retained

All 11 procedural palms/canopy/wet/upland/dead trees are harvestable with `GameplayResource` collision. Living trees use existing `leafy_tree`, dead trees use `dry_tree`. No new `palm_tree` resource is introduced. The existing spawner/promoter handles axe gating, stable TreeId, measured trunk, falling, depletion/regrowth and save/pooling state. Saplings are `Shrub/UnderstoryTree`, decorative and nonharvestable. Other decorative shrubs/ferns/understory/vines/groundcover are nonharvestable with collision None.

`shrub_forest_01` copies actual root `ResourceNodeView` + `FoodSourceView` and the sphere trigger from ES_BerryBush, **not its mesh**. The actual contract is berry_bush/berries, playerHarvestable false, edibleByHerbivores true, biomass 8, nutrition 1, regrowth 2, renderOnly false, disappear/deactivate when empty. Preserve these observed values rather than interpreting the species Harvestable flag as permission to invent player berry harvesting. Shrub Harvestable does not activate the tree promoter.

`groundcover_forest_01` similarly copies ES_GrassPatch: grass_patch/grass, playerHarvestable false, renderOnly true, edible plant food, biomass 5, nutrition 1, regrowth 1, disappear/deactivate when empty. Its existing root sphere is a trigger, never a blocking collider. Legacy template scales (.2 berry, .15 grass) are applied to trigger center/radius **and ResourceNodeView.interactionRadius**, which Awake reapplies. Thus the identity root preserves world-space radii .45 m and .3375 m rather than enlarging them to 2.25 m. Root layer/tag are retained. The existing GroundCover collision None policy disables colliders when spawned; food registration/consumption does not depend on them. Other decoration wrappers contain no food/resource components or blocking colliders.
